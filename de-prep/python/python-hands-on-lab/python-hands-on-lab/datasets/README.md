# Datasets

All data is synthetic and generated by `generate_datasets.py` (deterministic, `random.Random(42)`). Rerun it any time to reset:
`python datasets/generate_datasets.py`. Everything is **intentionally messy** — that's the point.

## `csv/`

| File | Rows | Columns | Messiness you'll meet |
|---|---|---|---|
| `customers.csv` | ~1,010 | customer_id, name, email, country, city, signup_date, segment, is_active | blank emails, invalid emails (`.at.`), lowercase countries, `DD/MM/YYYY` dates, upper-cased/padded names, ~15 near-duplicates (case/whitespace) |
| `products.csv` | 200 | product_id, name, category, price, currency, active | some blank categories, inactive products |
| `orders.csv` | ~5,250 | order_id, customer_id, product_id, quantity, unit_price, order_ts, status, updated_at, channel, country | exact duplicates, newer versions of the same order (later `updated_at`), 0/negative quantities, `N/A` prices, blank/unknown customers (`C99999`), invalid timestamps, lowercase statuses; rows are shuffled |
| `transactions.csv` | ~10,150 | txn_id, account_id, ts, amount, currency, type, merchant, status | signed amounts, 3 currencies, failed/pending, 150 duplicates |
| `employees.csv` | 300 | emp_id, name, email, department, title, manager_id, salary, hire_date, location, status | manager hierarchy, missing salaries, terminated staff |

## `json/`

- `customers.json`, `products.json` — clean JSON arrays.
- `orders_nested.json` — 1,000 orders with nested `customer{contact{}}`, `items[]`, `payment{}` (sometimes missing), `shipping{address{}}`, `tags[]`, some orders with no items.
- `events.jsonl` — 5,000 clickstream events (JSON Lines) with nested `properties`/`device`; ~1% truncated lines; ~2% null `user_id`.
- `api/` — backing data for the mock REST API (`labkit/mock_api.py`): 237 customers (deliberately not a round number of pages), 538 orders (15 duplicated across pages,
  10 with `unit_price: null`), products, and 400 events with `updated_at` for watermark pulls.

## `logs/`

- `app.log` — ~22,500 lines / 20,000 entries over ~25 hours: `ts LEVEL [service] key=value ... msg="..."`, ERROR entries with multi-line Python tracebacks, and corrupted lines.
- `app_small.log` — the first 250 lines, for quick experiments.
- `access.log` — 5,000 Apache combined-format lines.

## `incoming/` — a landing zone

`orders_01.csv`, `orders_02.csv` (contains late corrections of `orders_01` rows), `orders_03.csv` (UTF-8 **BOM**, reordered columns, extra `coupon_code`), `corrupt.csv`
(ragged rows, unbalanced quote, non-CSV text), `customers.json`, a half-written `orders_04.csv.tmp`, and a `_SUCCESS` marker.

## `daily/` — partitions for incremental processing

`dt=2026-01-01/ … dt=2026-01-07/`, each with `part1`/`part2` CSVs. Day 3 contains **late duplicates** from day 2, day 5 has a **high reject rate**, day 6 contains
`orders_20260105_part1_redelivered.csv` — a byte-identical **re-delivery** of a day-5 file under a new name — and day 7 is **empty** (header only).

## `s3/` — simulated S3 (`<root>/<bucket>/<key>`)

- `lab-raw-bucket/sales/ingest_date=2026-01-1{0,1,2}/part-0000{0,1}.csv` and `lab-raw-bucket/customers/customers.json`
- `lab-processed-bucket/` (empty, outputs go here)
- `lab-config-bucket/jobs/daily_sales.json` — a Glue-style job config

## `config/`

`pipeline.json` (sample pipeline config) and `.env.example` (environment-variable overrides).
